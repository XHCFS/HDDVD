1. .ACA  (Advanced Content Archive)
================================================================

SOURCE (primary, reference implementation): literal strings inside
HDDVDPLAYDLL, extracted from SCENACA.msi (Sonic Scenarist Advanced
Content 4.5, 2007-09-27), archive.org item "scenarist-hd-dvd-45".
The DLL itself is not kept in this tree; the strings that matter are
copied below. Re-extract from that IA item if you need the binary.

Validation messages emitted by the ACA parser (verbatim):
    "Archive header ID is not 'HDDVDACA'"
    "Archive header version is not 1.0"
    "Archive header file type is not 0"
    "Archive header encoding type is not 1"
    "Archive size is less than size of header"
    "Buffer too small to get archive size"
    "Invalid archive file header"
    "invalid archive format"
    "Index exceeds number of files in archive"
    "archive index out of range"
    "CRC error"
    "File Cache: '%s' does not exist in archive"
    "File Cache: Unable to get font file data from archive"
    "File Cache: Could not determine archive size from advanced stream packet"
    "HDArchive"

=> Header therefore carries, at minimum:
     - 8-byte magic          : ASCII "HDDVDACA"
     - version               : must be 1.0 (major/minor)
     - file type             : must be 0
     - encoding type         : must be 1
     - total archive size    : compared against actual size
   followed by a file index addressed by integer index
   ("Index exceeds number of files in archive").

2. Advanced Stream Pack (ADV_PCK) - byte level
================================================================
SOURCE (primary-ish): Toshiba HD DVD patent family. Working extracts:
`spec/raw/patents/US20070091495A1_architecture.txt`,
`US20080298219A1_byte_tables.txt`.
Live: https://patents.google.com/patent/US20070091495A1
(and US20080298219A1, WO2006098395A1).

    "a playlist application resource PLAPRS is divided into each data
     consisting of 2048 bytes, and packed in an advanced pack ADV_PCK
     every 2048 bytes"

    "one pack size, one logical block size, and one logical sector size
     are equal to each other, i.e., 2048 bytes"

    "An ADV_PCK ... comprises a pack header and Advanced packet (ADV_PKT).
     Advanced data (Advanced stream) is aligned to a boundary of logical
     blocks. Only in case of the last pack ... when the ADV_PCK length
     including the last data of the Advanced stream is smaller than 2048
     bytes, that pack length can be adjusted to have 2048 bytes."

    "in the data structure of the advanced pack ADV_PCK, a pack header
     PHEAD, a packet header PHEADA, a sub-stream corresponding to an
     advanced pack ADV_PCK, an advanced data header ADDTHD, and advanced
     data ADVDT are arranged in that order."

    "The stream_id of this ADV_PCK is, e.g., 1011 1111b (private_stream_2),
     and its sub_stream_id is, e.g., 1000 0000b."

    "packet_start_code_prefix field has a value '00 0001h', a stream_id
     field=1011 1111b specifies private_stream_2, and a PES_packet_length
     field is included. The Advanced packet has a Private data area, in
     which a sub_stream_id field=1000 0000b specifies an Advanced stream,
     a PES_scrambling_control field assumes a value '00b' or '01b'
     (Note 1), and an adv_pkt_status field assumes a value '00b', '01b',
     or '10b' (Note 2). Also, the Private data area includes a
     loading_info_fname field (Note 3) which describes the filename of a
     loading information file which refers to the advanced stream of
     interest."

=> ADV_PCK: 2048-byte pack; PES packet_start_code_prefix 0x000001;
   stream_id 0xBF (private_stream_2); sub_stream_id 0x80 (Advanced stream);
   private data area carries PES_scrambling_control, adv_pkt_status and
   loading_info_fname.
