# S4. Program Chain and the navigation-command VM

*Values are from `RESERVOIR_DOGS` [11]. No patent RBP table exists for the PGC body or
the command encoding, so everything here is disc-derived and graded **SINGLE** unless
noted.*

The Program Chain (PGC) is the unit of playback: an ordered list of programs and cells
plus pre, post, and cell command blocks executed by a small register VM. This is
DVD-Video's model, kept intact and widened.

## 4.1 PGC layout

The header offsets moved ahead of the palettes, and there are two palettes. `[11]`
`[SRC: DERIVED | arithmetic closure on PGC 1]` **SINGLE**. Closure on PGC 1:
`cell_playback` at 386, plus 58 cells at 28 bytes, is 2010, which equals
`cell_position_offset`; 2010 plus 58 times 4 is 2242, which equals the next PGC start.

| Offset | Size | Field | vs DVD |
|---|---|---|---|
| 0x00 | 2 | `nr_of_programs` | u8 at 0x02 |
| 0x02 | 2 | `nr_of_cells` | u8 at 0x03 |
| 0x04 | 4 | `playback_time` | same (BCD, §4.4) |
| 0x08 | 4 | `prohibited_ops` (UOP) | same |
| 0x0C | 16 | `audio_control[8]` (u16) | same |
| 0x1C | 128 | `subp_control[32]` (u32) | same |
| 0x9C | 2 | `next_pgc_nr` | same |
| 0x9E | 2 | `prev_pgc_nr` | same |
| 0xA0 | 2 | `goup_pgc_nr` | same |
| 0xA2 | 1 | `pg_playback_mode` | same |
| 0xA3 | 1 | `still_time` | same |
| 0xA4 | 4 | reserved | new |
| 0xA8 | 2 | `command_tbl_offset` | DVD at 0xE4 |
| 0xAA | 2 | `program_map_offset` | DVD at 0xE6 |
| 0xAC | 2 | `cell_playback_offset` | DVD at 0xE8 |
| 0xAE | 2 | `cell_position_offset` | DVD at 0xEA |
| 0xB0 | 64 | palette 1 (16 x u32) | DVD at 0xA4 |
| 0xF0 | 64 | palette 2 (16 x u32) | DVD has one |

The two palettes were byte-identical on the specimen; the purpose is unconfirmed,
likely SD versus HD or 4:3 versus 16:9 variants. Do not assume they always match.
`audio_control` had exactly 6 non-zero entries (equal to `VTS_AST_N`) and `subp_control`
had 5 (equal to `VTS_SPST_N`).

## 4.2 cell_playback: 28 bytes (DVD has 24)

`[11]` `[SRC: DERIVED | chain-validated across 204 cells]` **SINGLE**. Chain validation:
every cell's `first_sector` equals the previous cell's `last_sector` plus 1, across all
204 cells. DVD's 24-byte layout holds, with 4 trailing bytes appended (zero on the
specimen).

| Offset | Size | Field |
|---|---|---|
| 0x00 | 2 | cell category and flags |
| 0x02 | 1 | still_time |
| 0x03 | 1 | cell_cmd_nr |
| 0x04 | 4 | playback_time |
| 0x08 | 4 | first_sector |
| 0x0C | 4 | first_ilvu_end_sector |
| 0x10 | 4 | last_vobu_start_sector |
| 0x14 | 4 | last_sector |
| 0x18 | 4 | reserved (new) |

`cell_position` stays 4 bytes (`vob_id` u16, reserved u8, `cell_id` u8).

## 4.3 The navigation-command VM: DVD's instruction set, rotated 16 bits

The HD DVD command word is the DVD-Video command word rotated right 16 bits. `[11]` (57
commands across 12 IFOs) `[SRC: SRCCODE | libdvdnav src/vm/vmcmd.c]` **SINGLE**.

```
DVD[0..5] = HD[2..7]      DVD[6..7] = HD[0..1]
```

The command table header is DVD-shaped (`nr_pre`, `nr_post`, `nr_cell`, `last_byte` as
u16), and commands are 8 bytes as in DVD. The proof is statistical. Across all 57
commands `byte[0]` is `0x00` every time, so it cannot be the opcode; the type field is
at `byte[2]`. Testing `byte[2]>>5` yields the set {1, 2, 3}, which is DVD's Link/Jump,
SetSystem, and Set, while the raw reading yields type 0 (invalid) for everything.

| Reading | Type histogram |
|---|---|
| raw bytes | {0: 57}, all invalid |
| rotated | {1: 16, 2: 5, 3: 36} = Link/Jump, SetSystem, Set |

Decoded with libdvdnav's own bit positions, the semantics are coherent:

| Source | Bytes | Decodes as |
|---|---|---|
| VMG first-play | `00 11 30 02 00 00 00 0f` | JumpTT 15 |
| VTS1 PGC1 post | `00 00 30 08 00 00 00 92` | CallSS VTSM (call VTS menu) |
| VTS1 PGC1 pre | `00 00 41 00 00 81 82 00` | SetSystem op=1 (audio, subp, angle) |
| various pre | `00 00 71 00 00 0a 00 00` | Set GPRM, immediate 10 |

A first-play that jumps to a title and a feature PGC whose post-command calls the VTS
menu are exactly the expected shapes. libdvdnav's `vm.c` and `vmcmd.c`, and the VM
itself (16 SPRM and 16 GPRM registers; Link, Jump, Call, SetSystem, Set, and Compare
families), are reusable after a single 16-bit rotation at command load. `[SRCCODE]`.

Caveat on the Set-operand register field. The GPRM register field decoded as `g0` for
every Set command, which is implausible. libdvdnav has three `print_set_version_*`
variants with different register bit positions, and the correct one is not yet
established. The type dispatch is solid; the Set operand layout needs a second specimen.
**OPEN**.

## 4.4 playback_time: one unresolved detail

The format is DVD's BCD (hour, minute, second, frame). The frame byte's top 2 bits are
`0b10` (25 fps) in all 204 cells, which is DVD's frame-rate encoding and consistent with
PAL. The seconds byte carries 2 additional varying bits (`0b10` in 128 cells, `0b11` in
76), which DVD does not have. Masking them yields valid BCD in 204 of 204 cells, so the
mask is right, but the bits are not frame rate (both values occur within one PGC) and
their meaning is **OPEN**.

## 4.5 Menu PGC category (`HDVTSM_PGC_CAT` and `HDVMGM_PGC_CAT`)

Patent [3] FIG.8 (VMG menu) and FIG.27 (VTS menu) give a 4-byte category word: entry
type (b7), block mode and type, audio-info selection (audio in VOB stopped, continued,
or ignored, plus `HDMENU_AOBS` triggering), audio number, and `PTL_ID_FLD` (upper and
lower). These drive menu-PGC selection and the still-menu audio object `HDMENU_AOBS`,
the HD analogue of DVD's menu audio. The bodies were not decoded on the specimen, so the
layout is from patent only and graded **OPEN**.
